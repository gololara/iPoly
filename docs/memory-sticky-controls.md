# Memorias: contracting header and capture FAB (local review)

Second iteration on refactor/memory-sticky-controls, based on 2a8f85f. The owner corrected the previous fixed-header approach: one document scroll, a real shrinking/sweeping transition, and only logo + full text search + history trigger in the compact state. Language, navigation, title and selection summary return at the top. No publication or changes to APIs, MCP, schema, access, dependencies or real data.

The header uses one persistent instance of each control and a fixed expanded-height spacer. Its geometry follows document scroll directly from 292px to 64px over 228px, so content does not jump when the header contracts. A minimum document range keeps the compact search in place when a loading/short result set replaces a long list; the first result remains directly below the compact header. Outgoing controls fade and sweep away, become inert, and leave keyboard navigation; a focused outgoing control stays expanded until focus leaves. The logo returns to the start. Reduced motion removes the decorative sweep and animations. History remains a multi-select overlay with count and accessible full labels; opening it does not insert a new scroll region to hide navigation.

A 56px capture FAB replaces the full footer. Its accessible name distinguishes new capture, an existing draft, and draft loading. Capture data, saving and draft persistence are unchanged. Only its close-focus callback is scoped to Memorias so Escape or close restores focus to the new FAB; legacy routes retain their behavior. Bottom space and focus margins keep the last card reachable above the FAB; safe-area insets are honored. On coarse-pointer devices it hides while the search field has focus, avoiding the mobile keyboard area.

The same isolated preview has an explicit --long-list option that adds eight synthetic memories to its ephemeral database for realistic scrolling. No production import or persistence is involved, and default fixtures/tests stay unchanged.

Acceptance: document is the only browsing scroller; intermediate and compact geometry; only three compact header controls; repeated down/up, no layout jump, input identity/text/focus, hidden-control tab order, filters and interrupted reads, reduced motion, 320/390/430/1280 widths, short viewport and FAB focus/capture/draft survival. Verify in actual Chrome on the Mac with the existing synthetic profile, and retain initial/compact screenshots. Physical iPhone and an actual on-screen keyboard are outside emulation coverage.
