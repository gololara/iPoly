# Contribute to iPoly

Fork the repository, make a focused change on a branch, and open a pull request to `main`. Describe the user-visible change, the checks you ran, and any effect on existing installations. Use synthetic data in examples, screenshots, logs, and tests.

## Review a pull request

1. Read the description and open **Files changed**. Check that the change matches its stated scope. For storage changes, review the migration and check that existing memories, authorship, and attachments still open.
2. Open **Checks** and inspect **Verification**. For visible changes, preview the feature using a fresh local installation or a private test Site with synthetic records.
3. Use **Review changes** to approve or request changes. Resolve review conversations and merge when the required checks pass. New commits after an approval need another review.

For setup and commands, see [local development](LOCAL-DEVELOPMENT.md). A merge on GitHub does not deploy a private installation. Maintainers can publish a tagged release after verification, and installation owners choose when to upgrade.
